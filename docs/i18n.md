# Languages & localization

## Current (MVP)

The frontend supports a **English / French toggle** in the header. The choice is saved in `localStorage` (`mboa_locale`).

Strings live in `frontend/src/lib/translations.ts`. Pages wired so far:

- Home hero and stores section
- Header navigation
- Search placeholder

Add new keys to both `en` and `fr` objects, then use `t("key")` from `useI18n()`.

## Planned

| Phase | Languages | Notes |
|-------|-----------|--------|
| **Now** | English, French | Toggle in header; Cameroon’s two official languages |
| **Later** | Traditional / regional languages | e.g. Ewondo, Duala, Bamileke, Fulfulde — for sellers and buyers who prefer them in the UI |

Traditional languages are **not implemented yet**. When added, the toggle will expand (or become a language picker) without changing the discovery + phone-contact product model.

## Implementation notes (for future sprints)

- Keep all user-facing copy in `translations.ts` (or split per locale file if it grows).
- Product listing content (store descriptions, product titles) stays in whatever language the seller writes — the UI language only affects chrome/labels.
- Consider `Accept-Language` or a `locale` query param only if we add server-rendered pages or emails later.
